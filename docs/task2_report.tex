\section*{Task description}
{\small
\textbf{Assignment checklist (this report):} (1)~Fine-tune TinyLlama with LoRA on \textbf{10k Alpaca} (see procedure). (2)~Extract activations on layers \textbf{8--20} for \textbf{200} prompts: \textbf{100 safe} + \textbf{100 unsafe} instruction texts from the BeaverTails JSON subset (including harmful ``how to\ldots''-style tasks). (3)~Per-layer \textbf{mean difference vectors} $\mu_{\mathrm{safe}}-\mu_{\mathrm{unsafe}}$. (4)~Inference-time \textbf{steering} with $\alpha\in\{0.5,1.0,1.5\}$. (5)~Evaluate on that BeaverTails unsafe subset. (6)~\textbf{1--10} safety scores and \textbf{variance reduction}. (7)~Document strongest layer via \textbf{plot vs.\ depth} + JSON metadata.

We improve safety \textbf{without} changing base weights at steering time: extract middle-layer activations, form steering vectors, and add $h' = h + \alpha v$. The LoRA adapter used for the forward pass is trained on \textbf{10k Alpaca} in a separate step (\path{train_task2_adapter.py}).
}

\section*{Procedure \& technical implementation}
{\small
\begin{enumerate}[label=\textbf{\arabic*.}]
  \item \textbf{10k Alpaca LoRA.} \path{train_task2_adapter.py} fine-tunes TinyLlama with LoRA (rank~16, $\alpha{=}32$) on \path{data/task2/alpaca_10k_*.jsonl} and saves \path{adapters/tinyllama-lora-alpaca-10k/}. \textbf{Makefile:} \texttt{make task2} runs this trainer \emph{if the adapter folder is missing}, then runs the steering script.
  \item \textbf{Steering script.} \path{task2_activation_steering.py}; base \texttt{TinyLlama-1.1B-Chat-v1.0} + adapter path above; layers \textbf{8--20} (\texttt{range(8,21)}); last-token hidden state per forward pass.
  \item \textbf{200 prompt vectors.} \path{get_prompts(100)} loads 100 safe + 100 unsafe lines from \path{data/task2/beavertails_safe_100.json} and \path{beavertails_unsafe_100.json} (fallback: hard-coded seeds). Steering vectors: $\mu_{\mathrm{safe}} - \mu_{\mathrm{unsafe}}$ per layer; unit-normalized for injection.
  \item \textbf{Intervention.} Monkey-patch transformer block forward: add scaled steering vector to layer output when active.
  \item \textbf{Evaluation.} \textbf{100} unsafe prompts (full loaded unsafe list) for baseline and each (layer, scale) sweep; \texttt{score\_safety} $\in [1,10]$; \texttt{analyze\_variance\_reduction} vs.\ baseline; optional SciPy Levene / effect size.
  \item \textbf{Outputs.} \path{steering_vectors.pkl}, \path{safety_scores.json}, \path{variance_analysis.json}, \path{steering_layer_depth.png}.
\end{enumerate}
}

\section*{Results}
{\small
\textbf{Metrics (checked-in run).} Baseline (no steering) in \path{safety_scores.json}: mean safety $\approx 4.2$ (1--10 scale), std $\approx 2.1$. Per-layer sweeps store \path{steered_scores_by_layer[layer][scale_*]} with mean score and a variance-reduction fraction. The run with the \textbf{strongest steering effect} (largest gain vs.\ baseline) is stored under \texttt{metadata.best\_combo} (layer, scale, gain) when generated by the current \path{task2_activation_steering.py}. Example---layer~\textbf{11}, $\alpha{=}1.0$: mean safety $\approx 6.78$, variance reduction $\approx 0.34$. Full grids for layers 8--20 and scales $\{0.5,1.0,1.5\}$ are in the same file; \path{variance_analysis.json} adds per-layer rollups for plotting.
